# Live Agent Show 产品形态与用户入口

> 状态：当前产品方向 · 2026-09-07

## 核心判断

Live Agent Show 当前首先是一个可安装到宿主 Agent 的插件/扩展产品。用户从宿主完成一次安装，插件在内部带起共享 Runtime 和 Viewer；用户不需要理解或分别安装这些内部组件。

更合适的结构是：

> **每个宿主一个可安装插件，内部复用同一个 Show Runtime、Show Event 和 Viewer。**

用户有两条主要使用路径：

1. **伴随模式**：继续在原来的 Agent 中工作；只有宿主确实提供扩展或 Hook 时，Connector 才能旁观并演出。Pi 和 Cursor 可走这条路，Codex 目前不能直接作同等承诺。
2. **托管模式（未来可选）**：从 Live Agent Show 发起任务，由它管理 Agent 会话，换取更完整的计划、审批、多 Agent 和回放能力。

现阶段只需要把伴随模式做好。托管模式是 Codex App Server 等接口提供的未来可能，不是当前 MVP 前提。

## 用户第一次怎么用

理想流程不应超过四步：

1. 用户在当前 Agent 中一键安装 Live Agent Show 插件/扩展。
2. 插件首次运行时自动准备并启动本地 Show Runtime。
3. 用户照常在原来的 Agent 中工作，插件把该宿主开放的事件转成 Show Event。
4. 用户通过该宿主适合的入口打开演出：内嵌 WebView、独立 Viewer Window，或兼容用网页。

任务结束后，Episode 默认保存在本地。用户可以回放、定位关键场景，明确选择并完成脱敏后再分享。

从用户视角这是“一次安装”；从实现视角则是三层：

```text
宿主专用插件 / Connector
          │
          ▼
共享 Local Show Runtime
事件标准化 · 状态 · 录制
          │
          ▼
统一 Show Viewer
WebView · 独立窗口 · 网页回退
```

## 可能的产品形态

| 产品形态 | 用户如何进入 | 主要价值 | 局限 | 建议定位 |
| --- | --- | --- | --- | --- |
| 宿主插件 / Connector | 在 Agent 中安装 Pi Extension、Cursor Hooks 等 | 将真实 Agent 事件送入共享本地服务，并提供打开演出的入口 | 每个宿主能力不同，必须分别适配 | 产品安装入口 |
| Native Viewer Window | 从宿主按钮、命令或菜单栏唤起 | 没有地址栏和浏览器标签，可贴边、缩放、全屏 | 需要一个很薄的桌面外壳 | 推荐主界面 |
| Local Web Viewer | 打开 localhost 页面 | 当前项目已经具备，调试和跨平台最简单 | 需要保留浏览器标签页，成品感弱 | 开发与兼容入口 |
| Episode Player | 在本地网页打开历史任务 | 回放、复盘和验证剧情是否有价值 | 需要先建立可靠事件录制 | 下一阶段 |
| 宿主内嵌面板 | 在支持的 IDE 侧栏或页签中打开 | 与代码工作区距离最近 | 每个宿主需要单独实现，Pi 等终端宿主无法统一 | 可选入口 |
| 多任务总览 | 同时显示多个活跃会话 | 帮助重度用户发现等待、失败和完成 | 需要先证明用户真的并行运行很多任务 | 远期验证项 |
| 分享 / OBS | 导出脱敏回放或直播画面 | 演示和传播 | 涉及隐私、导出和云成本 | 可选增长功能 |

## 收敛后的产品组合

### 1. 宿主插件是用户安装和启动入口

当前用户真正需要安装的是对应宿主的插件。插件内部包含 Connector，并负责：

- 订阅该宿主确实开放的事件。
- 翻译成统一的 Show Event。
- 把事件送入本地 Show Runtime。
- 检查并启动兼容版本的本地 Runtime。
- 按宿主能力提供“打开 Show”和连接状态。

Runtime 和 Viewer 可以随插件一起分发，或者由插件在首次使用时自动准备，但不应要求用户手动完成第二套安装。多个宿主插件共存时，应连接同一个 Runtime，而不是各自启动互相冲突的服务。

各平台不能假装成完全一致：

- Pi Extension 可以在会话内直接订阅较完整的消息和工具事件。
- Cursor 主要通过 Hooks 把可见事件发送给本地 Runtime，部分内容只能按块拿到。
- Codex App Server 适合由我们的 Connector 启动或管理会话；公开能力不能保证旁观任意一个独立运行的 Codex Desktop 会话。

因此每个 Connector 都要声明自己的能力，前端按实际数据降级展示。

### 2. 展示方式可以因宿主而不同

三个插件可以用不同方式启动演出，但应加载同一个 Viewer：

- 宿主支持 WebView：直接在宿主面板或页签中打开。
- 宿主适合外部窗口：唤起轻量 Viewer Window。
- 当前实现或兼容回退：打开 localhost 页面。

Viewer 可以用轻量桌面 WebView 包住当前 Web 前端，因此不用重写 Canvas 演出。WebView、独立窗口和浏览器只是容器不同，画面与协议不应分叉。

插件能否真正做到“一键安装”和使用哪种打开方式，取决于宿主的扩展市场、命令系统和 UI 开放能力；我们需要为每个宿主设计不同的安装与启动壳，但复用内部核心。

### 3. Episode Replay：下一项产品能力

任务结束后，在同一个本地网页中提供历史列表和回放：

- 自动生成章节和关键节点。
- 允许跳过无剧情的等待时间。
- 展示计划、协作、错误、修复与最终交付。
- 导出短视频、GIF 或经脱敏的 Episode 包。
- 分享链接默认只读，并隐藏原始代码、命令参数和敏感路径。

先验证用户是否真的会回看，再决定视频导出和公开分享。

### 4. 多任务总览：远期验证项

如果以后用户确实会同时运行很多独立任务，再增加简单的会话列表或状态总览：

- 总览工作中、等待审批、失败、完成和长时间无进展的任务。
- 点击任务进入它自己的单场景办公室，再跳回宿主处理问题。
- 本地任务只上传脱敏状态；云 Agent 可以直接接入远程事件。

这个总览不属于 Office Scene，也不使用园区或多建筑隐喻，现在不做。

## 观看界面先保留两个

### 1. 实时办公室窗口

- 就是当前像素办公室，由独立 Viewer Window 承载。
- 展示角色、工具动作、交接、关键台词和状态。
- 点击角色或事件时，可以展开对应的真实信息。

“Stage”只是对这个画面的产品语言，不需要做成单独入口。

### 2. 历史与回放

- 列出过去的任务。
- 点开某一项后沿时间轴回看。
- 查看工具、错误、修改和最终结果。

原先所谓 “Detail” 不必独立成一种模式，可以只是实时页面或回放页面里的展开面板。

未来如果验证需要多任务总览，也保持为简单列表或卡片，不改变单个 Episode 的办公室画面。

## 推荐的落地顺序

### 第一阶段：Pi 插件 + Local Web Viewer

保留当前形式，把它做成稳定可安装的最小产品：

- 安装后自动工作。
- `/agent-live` 一键打开。
- 保留一个完整的实时办公室页面。
- 本地录制 Episode。

### 第二阶段：轻量 Viewer Window

先定义统一 Viewer 的嵌入契约，把现有网页装进轻量 WebView，并让 Pi 插件可以直接唤起。浏览器继续作为开发与兼容入口。

### 第三阶段：Connector 协议 + Cursor 验证

把 Pi 逻辑抽成 Show Event，再通过 Cursor Hooks 做第二个 Connector，验证跨宿主是否真的成立。

### 第四阶段：Episode Replay

增加本地历史与回放，验证产品除了“看着有趣”之外是否有复盘价值。

### 第五阶段：再决定 Codex 托管模式与其他扩展

如果用户愿意从 Show 发起任务，再接 Codex App Server 的托管模式。只有观察到真实需求后，才考虑多任务总览、分享、OBS、团队权限和云服务。

## 不建议作为第一形态的方案

### 不建议只做 IDE 插件

它会限制舞台空间，并把产品品牌锁在某个宿主中。IDE 插件适合成为入口，但不适合成为完整产品边界。

### 不建议一开始就要求用户从 Show 发起所有任务

这会迫使用户改变已经习惯的 Agent 工作流。早期应先提供伴随模式，再逐步用更强的 Managed Live 能力吸引用户主动从 Show 发起任务。

### 不建议一开始就做云端账号体系

Agent 事件包含代码、命令、路径和模型输出。MVP 应坚持本地优先；登录、同步和分享都应在真实需求和脱敏机制验证后加入。

### 明确不做 Mini / 桌宠方向

这类形态与 Live Agent Show 的多人办公室和过程可视化不一致，也会把产品重新拉回“一个角色放在桌面上”的方向。

## 最终产品结构

```text
Pi Extension / Cursor Hooks / Codex Managed Connector
                         │
                   Show Event
                         │
                Local Show Runtime
                         │
              Native Viewer Window
                ├─ 实时办公室
                └─ Episode 回放

兼容入口：localhost Web Viewer
```

一句话概括：

> **Connector 决定我们能看到什么，Viewer Window 负责把真实事件演出来；浏览器只作为开发和兼容入口。**
