# Agent Live 产品文档

> 版本 0.1.0（原型）· 最后更新 2026-09-07

> 长期产品方向：**Live Agent Show**。当前只做 Demo 规格的单层办公室；真实 Agent 工作驱动主线，Preset 组合八类可替换内容，Environment 统一管理时间、外部天气、照明和 NPC 班次；一次 session 是一个可实时展示和回放的 Episode。详见 [产品愿景](VISION.md)。

> 当前实现：原版 Demo 作为冻结的视觉与行为基线保留；V2 已用配置化内容和原生 renderer 完成 1:1 复刻，后续产品开发以 V2 为准。两者共用同一套 Agent 事件与 Office Runtime，因此当前用户体验没有分叉。

## 1. 一句话

把正在干活的 coding agent，实时渲染成旁边一间像素风办公室：谁在思考、谁去翻代码、谁把活派给了谁，一眼看得见。

## 2. 背景与要解决的问题

vibe coding 的体验断层在于：你把需求丢出去之后，屏幕上只有一段不断向下滚的文字流。三件事看不清楚：

| 看不清的事 | 现状 | 造成的后果 |
| --- | --- | --- |
| 它现在在干什么 | 思考内容折叠、工具调用一闪而过 | 不知道该等还是该打断 |
| 它把活派给了谁 | 子 agent 的输出混在同一条流里 | 并行编排时完全失去现场感 |
| 已经烧了多少 | token 与成本散落在各处 | 事后才发现代价 |

日志面板能解决第一件事，但它是"读"的界面，需要主动扫视。办公室是"瞥"的界面：余光扫一眼就知道现场状态，不用停下手里的活。

## 3. 产品定位

**放在 IDE 旁边的第二块屏，用于环境感知，不用于调试。**

- 它**不是**日志查看器：不追求信息完整，追求一眼可读。
- 它**不是**调试器：不提供断点、单步、回溯。
- 它**是**一个陪伴式状态显示器：像 CI 的流水线灯，只不过灯是会走路的小人。

推论：任何"需要点开才能看到"的信息都不属于主画面，只放在侧栏；主画面上只保留能被余光捕捉的信号（位置、姿势、颜色、粒子）。

## 4. 目标用户与场景

| 场景 | 用户 | 典型用法 |
| --- | --- | --- |
| 单人 vibe coding 陪伴 | 日常用 pi 写代码的人 | 左边 IDE，右边办公室，等待时看进度而不是发呆 |
| 多 agent 编排调试 | 写 subagent 工作流的人 | 观察并行几路、谁卡住、谁先交付 |
| 演示与分享 | 布道、路演、录屏 | `?demo=1` 不消耗 token 就能放一段完整协作 |

## 5. 核心隐喻

产品的全部设计都从这张对照表推导：

| 真实世界 | 办公室里的表现 |
| --- | --- |
| 一次 pi 会话 | 一间办公室 |
| 主 agent | 主管"阿派"，名牌金色，固定坐 0 号工位 |
| 子 agent（委派出去的） | 从左上角门口进场的外援，各有职位与配色 |
| agent 正在推理 | 头顶思考气泡，逐字打出 |
| 调用读取类工具 | 走到右侧档案柜，拉开抽屉，飞出纸张 |
| 调用命令行工具 | 走到服务器机架，指示灯加速闪烁，冒火花 |
| 调用编辑类工具 | 坐回自己工位打字，屏幕亮起代码行 |
| 派活给子 agent | 两人走到会议桌两侧面对面，纸条飞过去，对方头顶弹感叹号 |
| 子 agent 交付 | 头顶浮起对勾，走回门口下班 |
| token 与成本 | 顶栏总计 + 每张员工卡分项 |

第四条和第七条是这个产品存在的理由——**它们是文字流里最难表达、图形里最容易表达的两件事**。

## 6. 功能清单

### 6.1 员工

- 每个 agent 一个 8×20 像素的小人，程序化绘制（无图片素材）。
- 外观按 agent id 哈希稳定生成：肤色、发色、上衣。同一个 id 永远同一身打扮。
- 已知职位（`scout`/`planner`/`reviewer`/`worker`/`tester`/`writer`，以及 ChatDev 风格的 `ceo`/`cto`/`cpo`/`programmer`/`designer`/`counselor`/`hr`）走固定配色与中文职位名；未知角色回落到哈希配色 + "外援"。
- 名牌常显在头顶，主管金色、外援灰白。
- 头顶状态灯（pip）按状态着色，思考时呼吸闪烁。

### 6.2 思考气泡

- 蓝框气泡带思考小点，显示推理内容的**末尾约 52 字**（推理是流式的，末尾才是"现在在想什么"）。
- 逐字打出，每秒约 46 字，最多 3 行，超出截断。
- 停留 4.2 秒后消失。

### 6.3 说话与动作气泡

| 气泡类型 | 配色 | 内容 | 停留 |
| --- | --- | --- | --- |
| 思考 think | 蓝框 + 思考点 | 推理末尾 52 字 | 4.2s |
| 汇报 say | 灰框 | 回复开头 90 字 | 6.0s |
| 动作 do | 黄框 | 工具中文标签，如"执行 npm test" | 2.8s |

### 6.4 工位与动作

六类工位，工具调用会让小人走过去，工位同时亮起：

| 工位 | 触发的工具类型 | 现场效果 |
| --- | --- | --- |
| 自己的桌子 | 写文件、编辑、补丁 | 屏幕亮起彩色代码行，飞出按键粒子 |
| 档案柜 | 读文件、列目录、检索 | 抽屉逐层拉开，飞出纸张 |
| 服务器机架 | bash / shell / 执行命令 | 指示灯从 0.5s 周期加速到 0.09s，冒火花 |
| 白板 | todo / plan 类 | 马克笔画出增长的红蓝线条 |
| 电话桌 | 浏览器、网络请求、向用户提问 | 话机亮绿灯，两侧黄灯交替 |
| 会议桌 | 委派类工具 | 见 6.5 |
| 咖啡机 | 保留（暂无工具映射） | 冒热气 |

### 6.5 派活：双人研讨

借自 ChatDev 的"结对研讨"范式。一次委派的完整动画：

1. 子 agent 从左上角门口进场，冒一句"我来了"。
2. 主管走到会议桌左侧，子 agent 走到右侧，两人面对面。
3. 纸条从主管飞向子 agent，落点触发感叹号。
4. 子 agent 复述任务（气泡显示任务前 60 字）。
5. 双方各自散开去干活，主管状态转为"等待 N 位同事"。

同一时刻只播一场会面（多路并行委派会排队串行播放），避免动画重叠成一团。任一方在 5 秒内没走到位则强制进入交接阶段，防止卡死。

### 6.6 进出场

- 主管直接出生在工位上（会话开始时它就已经在了）。
- 子 agent 从门口走进来，交付完成后先走回门口再消失，而不是原地蒸发。
- 成功交付浮对勾，异常退出浮叉号。

### 6.7 侧栏

- **员工**：每人一张卡，含配色头像、姓名、职位、中文状态徽章、当前动作详情、token 与成本。主管排在最前，其余按进场顺序。
- **动态**：滚动日志，按类型着色（思考/汇报/工具/派活/上下线）。最多保留 220 条 DOM 节点。

### 6.8 顶栏

连接状态 pill、模型名、轮次与运行中标记、全员 token 与成本合计。任务条单独一行显示当前需求。

### 6.9 演示模式

`?demo=1` 或点击"演示"按钮播放一段约 30 秒的脚本化场景（给会话存储加 Redis 缓存：拆需求 → 查档案 → 派给 scout 和 planner → 各自干活 → 汇报 → 收尾）。**完全是前端假数据，不连接任何模型，不消耗 token。** 播完即停，不循环。

### 6.10 音效

默认关闭。开启后交接动作有两声方波提示音。惰性创建 `AudioContext`，异常时自动永久禁用。

## 7. 状态一览

| 状态 | 中文 | 状态灯 | 典型触发 |
| --- | --- | --- | --- |
| `idle` | 待命 | 无 | 一轮结束，坐回工位 |
| `thinking` | 思考 | 蓝色呼吸 | 推理流有新内容 |
| `working` | 工作 | 黄色 | 工具执行中 |
| `waiting` | 等待 | 紫色 | 委派后等子 agent |
| `talking` | 汇报 | 绿色 | 正文输出中 |
| `done` | 完成 | 绿色 | 子 agent 交付 |
| `error` | 出错 | 橙色 | 工具报错或异常退出 |

## 9. 使用流程

**第一次接入**

```bash
ln -sfn /Users/snail/projects/agent-office ~/.pi/agent/extensions/agent-office
```

重启 pi（或 `/reload`），扩展会在会话启动时自动拉起本地服务，状态栏显示地址。

**日常使用**

| 命令 | 作用 |
| --- | --- |
| `/agent-live` | 打开办公室页面 |
| `/agent-live demo` | 打开演示场景（不消耗 token） |
| `/agent-live status` | 打印当前地址（多会话时用来确认端口） |

**不启动 pi 单独看画面**

```bash
npm run preview   # 然后打开 http://localhost:7788/?demo=1
```

## 10. 非目标

明确不做的事，以及原因：

| 不做 | 原因 |
| --- | --- |
| TUI 内嵌 | 终端画不出像素动画，且会和 agent 输出抢屏幕 |
| 交互式操控（点小人下指令） | 会把"观察工具"变成"控制面板"，职责混淆 |
| 完整日志检索 | pi 自己的输出已经是完整日志，重复实现没有价值 |
| 多会话汇总看板 | 当前每个 pi 会话独占一个端口，各看各的；聚合是后续独立话题 |
| 远程访问 | 服务只绑 127.0.0.1，没有鉴权，不适合暴露 |

## 11. 已知限制

1. **多 agent 需要额外安装 subagent 扩展**。pi 本身没有内置子 agent，本项目按工具名通用识别委派行为；没装的话办公室里只有主管一个人。
2. **子 agent 的细节依赖委派工具回传结构**（`details.results[]`），字段名变了就只剩状态、没有细节。
3. **成本可能显示为 `$0.0000`**：部分模型或中继不回传成本字段，token 数正常但金额取不到。
4. **小人是程序化 `fillRect` 画的**，够用但谈不上精美。
5. **最多 8 个工位**，超出的 agent 会挤在最后一个座位。
6. **没有回放**：会话结束服务即关闭，历史不落盘。
