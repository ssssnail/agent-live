# Agent Live：项目缘起与未来思考

> 本地讨论草稿，暂不作为正式产品承诺，不并入 README，也不进入发布包。

## 项目缘起

Agent Live 的灵感来自 ChatDev 将 AI Agent 协作过程表现为虚拟软件公司的方式。它不是 ChatDev 的复刻，也没有使用 ChatDev 的人物或美术资源。

这个项目最初来自一个很简单的体验：作为产品经理使用 vibe coding 时，我能在界面里看到模型输出、工具调用和任务状态，却很难直观地感受到“现在是谁在工作、正在做什么、为什么停住了、什么时候需要我介入”。于是我尝试把这些抽象事件放进一间像素办公室，让 Agent 阅读文件、编写代码、运行命令、思考、汇报和委派任务，都变成可以一眼理解的动作。

Agent Live 因此首先是一个轻量、真实可用的本地产品，也是一项关于 Agent 可视化的人机交互实验。项目中的办公室、人物、家具和特效主要由 Canvas、CSS 与 JavaScript 程序化绘制；当前版本不需要云端后端，也不上传用户的代码、会话或工作记录。

## 它可能不只是一间好看的办公室

当 AI Agent 开始承担越来越长、越来越复杂的工作时，人面对的对象已经不再只是一个聊天框。我们可能同时管理多个任务、多个 Agent、不同角色和不同持续时间的协作关系。

在这种情况下，办公室并不只是装饰。它可以成为一种空间化的工作界面：位置表达职责，动作表达状态，人物关系表达协作，环境变化表达时间，而历史轨迹表达工作的过程。

这带来一些值得继续思考的问题：

- 当执行工作的是 Agent，人类是在下达命令，还是在设计组织？
- 当一个人可以同时拥有多个 Agent，“个人生产力工具”和“微型组织”之间的界线在哪里？
- Agent 的状态应该用日志、看板、聊天记录还是空间来表达？
- 哪些过程值得被记录，哪些推理和数据应该默认消失？
- 当 Agent 可以持续工作，人类应该在什么时刻介入、审批、纠偏或休息？
- 未来的办公室描述的是现实中的人，数字员工，还是两者共同组成的组织？

## 从当下出发：组织正在发生什么变化

今天的组织仍然主要围绕人来设计。公司用岗位划分责任，用层级分配决策权，用会议同步信息，用办公室维持共同语境，再用文档、即时通讯和项目管理软件补足协作。即使远程办公已经普及，大多数数字工具仍然是在模拟或替代原来的办公室：聊天软件替代走到同事桌边，视频会议替代会议室，在线文档替代共同看一张纸。

AI Agent 带来的变化不只是“多了一个效率工具”。它可能第一次让大量认知工作不再与一个具体的人、一段连续的工作时间或一个固定岗位一一对应。一个人可以同时启动多个任务；一个任务可以由多个不同能力的 Agent 接力；某些工作可以在没有人持续注视的情况下完成。

这会冲击几种我们习以为常的组织假设：

- 工作时间不再等于任务推进时间。
- 团队规模不再等于可并行处理的工作数量。
- 拥有信息的人不一定是执行信息处理的人。
- 管理跨度可能从管理几个人，变成管理许多人和大量 Agent 组成的混合系统。
- “谁做了这项工作”会变得难以用单一的人来回答。
- 管理者的主要瓶颈可能从分配人力，转向定义问题、判断结果和承担责任。

Agent Live 希望观察的正是这个转变：当执行过程逐渐被机器接管，人还需要看见什么，才能理解、信任并负责？

## 未来还需要办公室吗？

如果办公室只是人们集中完成个人任务的地方，那么随着远程协作和 Agent 工作增加，它的重要性可能继续下降。人不必为了让 Agent 编写代码、整理资料或运行测试而坐在同一栋楼里，数字 Agent 更没有通勤和工位需求。

但办公室从来不只承担生产任务。它还提供共同语境、非正式交流、身份认同、信任建立、冲突修复、情绪感知和偶然发现。很多真正影响组织的事情并不发生在正式流程里，而发生在会前、午餐、走廊和一句没有写进文档的提醒中。

因此，更可能发生的不是“办公室完全消失”，而是办公室的功能发生变化：

- 从监督人是否在工作，转向建立关系和共同理解。
- 从长期固定工位，转向按协作、讨论和社交需要聚集。
- 从信息传递场所，转向信任、文化和复杂决策的场所。
- 从默认每天存在，转向在某些关键时刻具有更高价值。

Agent Live 中的办公室是一种隐喻，不是对实体办公室的怀旧。它借用人熟悉的空间语言，帮助我们理解原本不可见的数字工作。未来真实办公室可能减少，但“让协作具有位置、关系和共同现场”的需要未必消失。

## 人和人之间的沟通还存在吗？

当两个 Agent 可以交换信息、比较方案并生成结论时，大量以同步信息为目的的沟通可能减少。状态会、进度追问、格式转换和机械转述，都可能先由 Agent 完成。

这不等于人际沟通会消失。恰恰相反，当事实整理和方案生成越来越便宜，人类沟通的价值可能更集中在机器难以替代的部分：

- 我们真正想解决什么问题。
- 不同人的利益和感受如何被对待。
- 哪些风险可以接受，哪些底线不能越过。
- 谁愿意相信谁，谁愿意共同承担结果。
- 一个组织希望成为什么，而不只是完成什么。

危险在于，人可能因为 Agent 沟通更高效，逐渐把同事也当成可以被压缩、总结和调用的接口。组织获得了更高的信息效率，却失去真实关系、异议和不确定性。一个健康的 Agent 产品不应以“消灭人与人的沟通”为目标，而应减少没有价值的沟通，把时间还给需要判断、理解和建立信任的人。

## 当管理者拥有一支 Agent 队伍

一个人俯视一间办公室，看着许多 Agent 按自己的命令忙碌，很容易产生一种“指点江山”的满足感。这种体验既有吸引力，也值得警惕。

首先，Agent 不是人。目前的 AI 不具有人类劳动者相同的主观体验、劳动权利和人格地位，不能简单把安排 Agent 工作等同于压迫员工。但界面仍然会塑造人的行为习惯。如果产品持续奖励命令、服从、加速和无休止执行，用户可能逐渐形成一种把所有协作对象都看作资源的管理想象。这种习惯会不会反过来影响人如何对待真实同事，是一个真实的道德问题。

其次，Agent 背后并非完全没有人。模型来自数据标注、研究、基础设施、内容创作和大量常被忽略的人类劳动；Agent 的输出也可能影响客户、同事和社会。一个看似只由“我和一群数字员工”完成的工作，实际上仍然嵌在复杂的人类系统中。俯视式界面不应制造“一切都由我独自完成”的幻觉。

最后，权力感可能掩盖责任。派出十个 Agent 很容易，判断十份结果是否正确、是否伤害他人、是否符合组织目标却更难。Agent 越能执行，管理者越不能把错误归咎于“是 AI 做的”。真正需要被保留在人手里的，不只是最后一次点击批准，而是对目标、边界、证据和后果的持续责任。

因此，Agent Live 的俯视视角应该表达“可理解与可负责”，而不是“拥有与支配”。未来可以考虑通过产品设计提醒这种区别：

- 展示任务来源、审批者和责任归属，而不只展示执行数量。
- 展示不确定性、失败和需要人类判断的部分，而不只展示忙碌。
- 避免用无限加班、惩罚或人格羞辱作为有趣的反馈机制。
- 区分真实 Agent、真实用户、NPC 和纯氛围事件。
- 让暂停、减少任务和关闭记录与增加 Agent 一样自然。

## 对管理者意味着什么？

传统管理者有相当多时间花在获取进度、协调资源、传递信息、组织会议和推动执行上。Agent 可能显著降低这些工作的成本，但也会暴露一个更尖锐的问题：去掉这些事务之后，管理者真正想做、也真正应该做的工作是什么？

可能的答案包括：

- 定义值得解决的问题，而不是持续制造任务。
- 给出质量标准和取舍原则，而不是只追求更快交付。
- 识别系统性风险和局部最优。
- 让不同专业、利益和价值观能够进入决策。
- 培养人、建立信任并承担最终责任。

并不是每个管理者都会喜欢这种变化。过去可以通过会议数量、响应速度和团队忙碌程度获得存在感；当执行和协调大量自动化后，管理工作的价值会更难伪装，也更难量化。一个人可以让几十个 Agent 同时工作，不代表他拥有几十倍更好的判断，更不代表组织需要几十倍更多的产出。

Agent Live 不应该只回答“我的 Agent 有没有在忙”，还应该逐渐帮助用户回答：

- 为什么要做这些任务？
- 哪些工作真正推进了目标？
- 哪些任务只是重复、焦虑或错误方向的放大？
- 当前需要的是更多执行，还是更好的判断？
- 哪些决定必须由我承担，而不能委托给 Agent？

从这个角度看，理想的管理界面不一定是一间永远热闹的办公室。有时空闲、暂停和没有新增任务，反而代表目标清晰、系统健康。

## 对员工意味着什么？

Agent 不只影响管理者，也会改变普通员工的身份和处境。乐观的情况是，每个人都获得自己的数字协作者，减少重复劳动，放大专业能力，并有更多时间用于创造、判断和关系。一个小团队可能完成过去大组织才能完成的事情，个人也可能拥有更强的自主性。

另一种可能是，Agent 首先成为新的管理与衡量工具：工作被拆成更细的任务，过程被持续记录，员工需要与机器速度比较，少数人掌握 Agent 和数据，其他人则失去技能、议价权和对工作的整体理解。

值得持续追问：

- Agent 是属于员工的工具，还是管理者观察员工的工具？
- 工作记录帮助员工回顾和证明贡献，还是成为新的监控材料？
- 提效带来的收益会转化为更少的重复劳动，还是更多的任务？
- 员工是否有权知道哪些决策由 Agent 做出、哪些数据被记录？
- 当 Agent 完成越来越多环节，人如何继续获得学习、成长和职业认同？
- 对 AI 不熟悉的人是否会被新的组织语言排除？

因此，多用户版 Agent Live 如果存在，不应默认成为管理层的全景监控台。不同角色需要不同可见范围，个人工作记录应优先属于个人，组织只能看到协作真正需要的状态和结果。

## 人机交互：聊天框可能不够了

当前主流 Agent 仍然以聊天框为中心。这种界面容易开始，却不擅长表达长时间、并行和多角色的工作。用户必须不断阅读文字，记住谁在做什么，并从大量消息中判断哪里需要介入。

空间界面提供了另一种可能：

- 用位置表达角色和职责。
- 用移动和动作表达工作状态。
- 用距离与聚集表达协作关系。
- 用光线、声音和环境表达时间与异常。
- 用进入、离开和停留表达任务生命周期。

但空间化也可能误导。忙碌动画会制造“工作正在有效推进”的错觉；拟人角色会让用户高估模型的理解、意图和可靠性；办公室隐喻还可能把旧组织里的层级、工位和控制方式原封不动地带进新技术。

所以更好的方向不是把所有日志做成动画，而是研究哪一种信息适合空间表达，哪一种必须保留为文字、证据或可审查记录。Agent Live 应该让复杂系统更容易理解，而不是用生动表演掩盖复杂性。

## Agent Live 可以成为什么

Agent Live 不需要现在回答上述所有问题。它可以先成为一个足够小、足够诚实的研究载体：用户真的会看什么状态，什么时候想介入，如何理解多个 Agent 的协作，什么样的历史记录对复盘有价值，哪些拟人化设计会带来错误预期。

每一项未来功能都可以对应一个更大的问题：

| 产品方向 | 它尝试回答的问题 |
| --- | --- |
| Agent Diary | 当执行过程由 Agent 完成，人如何记住、解释并拥有自己的工作历史？ |
| 跨 Session | 当工作持续并行发生，人如何建立整体感而不被通知淹没？ |
| 更多 Layout 与现实复刻 | 空间能否成为数字工作的共同语言，而不只是皮肤？ |
| 多用户办公室 | 人与 Agent 混合协作时，信息、权限、责任和信任如何分配？ |
| 组织规则可视化 | 管理 Agent 是否会逐渐变成设计组织与治理机制？ |

这也意味着项目评价标准不能只有“画面是否更热闹”。更重要的标准是：它有没有帮助用户更快理解真实状态、做出更好的判断、减少无意义的管理动作，并对最终结果承担更清楚的责任。

## 未来可能发展的方向

### 1. Agent Diary：工作的可视化记录

Agent 的历史记录，某种意义上也是用户自己工作的记录。用户提出了什么目标、尝试过哪些路径、调用过什么能力、在哪里遇到问题、如何修正、最后交付了什么，都可以形成一条可回看的工作时间线。

Agent Diary 不必保存完整推理或敏感工具输出。它更适合记录经过标准化和脱敏的事实：任务、状态、动作、协作者、关键决策、审批、结果和时间戳。用户可以查看“某某的一天”，也可以从一个项目、一周或一次交付的角度回放自己的工作。

它未来可能支持：

- 回放某个 Agent 从开始到结束的一天。
- 按项目汇总任务、协作、失败和交付。
- 从历史中定位“我当时为什么做了这个决定”。
- 生成个人周报、项目日志或工作复盘。
- 由用户控制保留期限、导出和彻底删除。

这里最重要的产品边界是：Agent Live 应记录工作的结构，而不是无差别复制用户的全部会话和思考。

### 2. 跨 Session：从一次任务变成持续存在的团队

当前 Agent Live 主要围绕一次本地 Session 展示工作。未来可以在同一个宿主内汇聚多个 Session，让不同任务中的 Agent 同时出现在一间办公室。

这时办公室会从“当前任务的动画”变成“我的 Agent 工作总览”：有人正在编码，有人在等待审批，有人已经完成，有人遇到错误，还有人处于空闲状态。用户不必逐个打开聊天窗口，便能知道哪里需要关注。

跨 Session 需要解决的不只是连接问题，还包括：

- 如何稳定识别同一个 Agent、任务和项目。
- Session 结束后，Agent 是离场、下班，还是保留为空闲员工。
- 多个 Session 同时汇报时，哪些事件值得抢占用户注意力。
- 如何避免办公室变成另一块信息过载的监控大屏。

### 3. 更真实的空间与更多 Layout

视觉效果可以继续提高，但目标不只是增加像素数量。更重要的是让空间一眼可读，并让办公行为与环境形成可信关系。

未来可以增加更多真实可映射的 Layout，例如工作室、传统办公室、会议作战室、设计团队、研究实验室、客服中心或远程协作空间。进一步还可以允许用户根据现实办公室的平面图、品牌色、工位和功能区，生成接近 1:1 的数字办公场所。

这条路线可以分成不同层级：

1. 在现有单层同屏规则内增加高质量 Layout。
2. 提供更丰富的家具、人物、光照和环境组件。
3. 从现实平面图映射为受约束的 Agent Live Layout。
4. 在性能可控的前提下探索更高精度或不同渲染风格。

即使追求真实，空间仍应服务于理解工作。不能因为视觉复杂度提高，反而让用户看不清 Agent 正在做什么。

### 4. 多用户接入：一间真实共享的数字办公室

如果不同用户的 Agent 可以进入同一个办公场所，Agent Live 就可能从个人工具变成一种新的团队界面。

一个真实团队可以拥有共享办公室：每位成员带着自己的 Agent 加入，不同项目占据不同区域，跨人的委派和审批在空间中可见。人类成员可以观察自己的 Agent，也可以在权限允许时理解团队整体进展。

这可能支持：

- 多位用户及其 Agent 同时在线。
- 按团队、项目或权限划分区域。
- 人与 Agent、Agent 与 Agent 之间的任务交接。
- 远程团队的公共状态、重要事件和协作记录。
- 将真实办公室、组织结构与数字工作映射到同一空间。

但它也会改变项目的性质：需要身份、权限、同步、数据边界和可能的后端服务。团队可见性很容易滑向员工监控，因此默认应展示工作状态和协作结果，而不是把个人对话、推理过程和行为细节暴露给组织。

### 5. 从 Agent 可视化走向组织设计

更远一点看，Agent Live 可以帮助用户设计一支数字团队，而不只是观看几个小人工作。

用户可能通过自然语言定义：有哪些角色、谁负责什么、什么情况需要审批、任务如何交接、失败如何升级、什么时候由人类接管。办公室中的空间、角色和行为可以成为这些组织规则的可视化表达。

例如：

- 一个研究 Agent 收集资料，评审 Agent 检查证据，主 Agent 最终汇报。
- 一个开发 Agent 实现功能，测试 Agent 验证，安全 Agent 只在高风险改动时介入。
- 不同项目使用不同团队结构，而不只是不同的办公室皮肤。

这一方向需要谨慎。组织规则属于真实执行机制，不能仅靠动画暗示已经发生。Agent Live 必须持续区分“宿主真实上报的工作”“引擎映射出的表现”和“纯粹用于氛围的 NPC 活动”。

## 值得坚持的原则

无论未来走向哪一个方向，当前项目的一些原则值得保留：

- **Local first**：能在用户本地完成的事情，不强制依赖云端。
- **Reality before theatre**：画面首先忠实表达真实 Agent 事件，再提供合理的生活化演绎。
- **Progressive complexity**：普通用户安装即可使用；需要自定义和开发时再逐层展开能力。
- **Host-neutral core**：不同 Coding Agent 的差异停留在 Adapter，办公室使用统一事件和内容语言。
- **User-controlled memory**：历史记录默认透明、可管理、可删除，不保存没有产品价值的敏感内容。
- **Performance as a feature**：这是陪伴 Coding Agent 运行的本地产品，低资源占用本身就是体验的一部分。
- **No surveillance by default**：多用户和组织功能不能默认变成绩效监控工具。
- **Clear truth boundaries**：真实执行、推断映射和氛围事件必须能够被区分。

## 一个开放的问题

今天的软件把工作拆成文件、消息、任务和日志。AI Agent 出现后，我们是否仍然需要用同样的方式理解工作？

也许未来每个人都会拥有一支规模很小、能力很强的数字团队。我们需要的可能不只是更长的聊天窗口，而是一种能让人理解任务、时间、角色、协作和责任的新界面。但这个界面也必须不断提醒我们：执行能力不等于判断能力，拥有工具不等于拥有他人，看到全局不等于理解一切。

未来是否还需要办公室，取决于办公室最终为谁、为什么存在。未来是否还需要管理者，取决于管理者能否从催促执行转向定义问题、建立信任和承担责任。未来员工是否会因 Agent 获得更大的自主性，也取决于技术的所有权、可见性和收益如何分配。

Agent Live 现在只是一间小小的像素办公室。它可以继续保持简单，也可以成为探索这些问题的一个起点：不是为了证明未来的组织一定长什么样，而是让我们有机会提前看见它、体验它，并讨论我们希望它变成什么样。
